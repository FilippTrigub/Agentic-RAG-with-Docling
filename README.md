# Agentic RAG MVP

A minimal retrieval-augmented generation (RAG) reference project that demonstrates how to:

- Parse PDF product specification sheets to structured JSON with [Docling](https://github.com/docling-project/docling).
- Embed rich document content and metadata using Google Generative AI embeddings.
- Store and query vectors locally with [Chroma](https://www.trychroma.com/).
- Orchestrate retrieval-augmented conversations with LangChain agents backed by Cerebras models.

The codebase is intentionally compact so you can experiment with ingesting your own product documents, tuning metadata filters, and exploring iterative tool-calling behavior.

---

## 1. Prerequisites

| Requirement | Notes |
| --- | --- |
| Python ≥ 3.13 | `uv` is used for environment & dependency management. |
| API keys | `GOOGLE_API_KEY` for embeddings, `CEREBRAS_API_KEY` for chat LLM. |
| Optional tooling | PDF specs to ingest (placed in `documents/`). |

> **Tip:** Copy `.env.example` to `.env` and populate required secrets before running commands.

## 3. Installation & Environment Setup

1. **Clone & enter the project**
   ```bash
   git clone <repo-url>
   cd rag-challenge
   ```

2. **Create & activate a virtual environment** (via `uv`):
   ```bash
   uv venv
   source .venv/bin/activate  # On Windows: .venv\Scripts\activate
   ```

   ```bash
   uv sync
   ```

4. **Configure environment variables**
   ```bash
   cp .env.example .env
   # Edit .env to include GOOGLE_API_KEY and CEREBRAS_API_KEY
   ```

## 4. Data Pipeline

### 4.1 Ingest PDFs to JSON (optional)

If you already have curated JSON files in `data/processed/`, you can skip this step.

```bash
uv run python ingest.py \
  --input-dir documents \
  --output-dir data/processed \
  --workers 4
```

- Each PDF is parsed by Docling to produce structured JSON capturing:
  - `content`: flattened plain text for embedding.
  - Section-based lists and tables (e.g., _Product features and benefits_, _Electrical Data_).
  - Metadata keys that align with index filters.
- Output JSON is written to `data/processed/<filename>.json`.

### 4.2 Processed JSON schema

A representative JSON file contains:

```json
{
  "source": "documents/ZMP_1004795.pdf",
  "content": "Unformatted textual content...",
  "Product features and benefits": ["Robust construction", "Consistent color"],
  "Areas of application": ["Stage & Theatre", "Studio"],
  "General Product Information": {
    "Product number (Americas)": "",
    "Product name (Americas)": "",
    "Family brand": "",
    "ANSI code": "FRJ"
  },
  "Electrical Data": {
    "Nominal wattage": "500W",
    "Nominal voltage": "240 V"
  },
  "...": "..."
}
```

During indexing, nested fields are flattened (e.g., `general_product_information`) allowing flexible substring filtering.

## 5. Building the Vector Index

You can build the Chroma index with either the module entry point or the CLI wrapper in `main.py`.

### Option A: Direct module invocation

```bash
uv run python -m rag_mvp.index_json \
  --processed-dir data/processed \
  --index-dir data/index/chroma \
  --collection rag_mvp
```

### Option B: Via `main.py`

```bash
uv run python main.py index \
  --processed-dir data/processed \
  --index-dir data/index/chroma \
  --collection rag_mvp
```

Both commands:

- Ensure directories exist (`data/processed/`, `data/index/chroma/`).
- Load every JSON document, flatten metadata, and embed content using `models/gemini-embedding-001` (requires `GOOGLE_API_KEY`).
- Persist vectors to the Chroma collection (`rag_mvp` by default).

The console output reports how many documents were indexed.

## 6. Chat Agent Usage

The chat agent requires both `GOOGLE_API_KEY` (for retrieval) and `CEREBRAS_API_KEY` (for the LLM).

### Option A: Module entry point

```bash
uv run python -m rag_mvp.agent \
  --index-dir data/index/chroma \
  --collection rag_mvp
```

### Option B: Via `main.py`

Start chat directly:
```bash
uv run python main.py chat \
  --index-dir data/index/chroma \
  --collection rag_mvp
```

Index then chat in one step:
```bash
uv run python main.py run \
  --processed-dir data/processed \
  --index-dir data/index/chroma \
  --collection rag_mvp
```

Once running:

- Type questions about product specifications.
- The agent **must** call the retrieval tool before answering; it may retry with different filters.
- Answers include citations like `[1]` referencing retrieved documents.
- Use `exit` or `quit` to close the session.

### Retrieval filters

The agent prompt encourages metadata filters such as:

- `general_product_information` contains `ANSI code: FRJ`
- `physical_attributes_dimensions` contains `GY9.5`
- `areas_of_application` contains `Stage & Theatre`

These filters allow precise control over which documents are surfaced.

Ensure the `.env` file is **not** committed (covered by `.gitignore`).

## 8. Troubleshooting

| Symptom | Checks |
| --- | --- |
| `uv` command not found | Install `uv` (https://github.com/astral-sh/uv). |
| "Missing embeddings" / errors using Google models | Verify `GOOGLE_API_KEY` is set and valid. |
| Cerebras authentication failures | Confirm `CEREBRAS_API_KEY` is exported. |
| No search results | Ensure `data/processed/` contains JSON files with non-empty `content`; rebuild the index. |
| Ingestion errors | Install Docling extras (`uv add docling`) and validate PDFs are accessible. |

## 9. Extending & Scaling

- Swap Chroma for a managed vector database (e.g., Qdrant, Pinecone) in `rag_mvp/tools.py`.
- Normalize numeric metadata during ingestion to enable range queries.
- Convert `rag_mvp.agent` to an async API server to handle concurrent sessions.
- Deploy as a container or serverless function; persist the index externally for horizontal scaling.
- Experiment with alternative LLMs or retrieval strategies by editing the agent/tool configuration.
